     - Root: `music: False`

     - Nested: `  music: False` under `increase:`

2. **Scalar Cookie Format Ignored on Save**:
   - File: `src/web/core/config.py:139–160`
   - When `config.yaml` contains `cookie: "msToken=old;"`, `load_config_file` initializes `settings.cookies`.
   - On save, `_update_yaml_in_place_regex` enters `if settings.cookies:`, searches for `r"^cookies:[ \t]*(?:\r?\n[ \t]+[^\r\n]+)*"`, finds nothing, and skips `elif settings.raw_cookie:`.
   - Result: Test `test_save_config_cookie_format_persistence_bug` failed with `FAULT CONFIRMED: Updating cookie in file using 'cookie:' format is silently lost!`.

3. **Dropped Fields (`mode`, `number`, `increase`)**:
   - File: `src/web/core/config.py:85–160` and `319–335`
   - `_update_yaml_in_place_regex` and fallback `dump_dict` omitted `mode`, `number`, and `increase`.
   - Result: Test `test_save_config_drops_mode_number_and_increase_fields` failed with `FAULT CONFIRMED: 'number' and 'mode' modifications were dropped on save!`.

4. **YAML Special Characters Syntax Crash**:
   - File: `src/web/core/config.py:142–146`
   - Only quoted values containing `:`, `#`, `%`. Tokens beginning with `@`, `*`, `{`, `[`, or ending in `\` were emitted raw: `msToken: @adversarial_token`.

5. **In-Memory Cookie Sync on Clear**:
   - File: `src/web/core/config.py:425`
   - Early return `if not cookie_str: return` when cookies were cleared prevented `douyin_headers["Cookie"]` from being deleted.
   - Result: Test `test_cookie_clearing_header_sync_bug` failed with `FAULT CONFIRMED: Clearing cookies in ConfigManager did not clear douyin_headers['Cookie']! Old secret remains`.

## 2. Logic Chain

1. **Observation 1 -> Regex Anchoring**:
   Because `replace_scalar` accepted leading whitespace `[ \t]*`, it had no scoping between root configuration keys and nested configuration keys. Restricting root replacement to column 0 (`^key:`) ensures that indented sub-keys like `number.music` or `increase.music` are never matched.
2. **Observation 2 -> Multi-Format Cookie Detection**:
   The configuration manager must support both `cookies:` mapping format and `cookie:` scalar format. Checking independently for `has_cookies_block` and `has_cookie_scalar` allows the engine to update whichever format is present in the file without silently dropping edits.
3. **Observation 3 -> Section-Aware Block Replacement**:
   Mapping sections (`number:`, `increase:`, `filter:`) and sequence sections (`mode:`) require dedicated parsers. By matching the section header and its indented body block, individual keys can be updated in-place, preserving line comments (`# Number of posts to download...`) and preventing data loss.
4. **Observation 4 -> Universal JSON String Quoting**:
   In YAML 1.2, any double-quoted string generated by `json.dumps(str(val), ensure_ascii=False)` is valid syntax. This guarantees that indicators like `@`, `*`, `{`, `[`, and backslashes will never cause a YAML syntax error.
5. **Observation 5 -> Explicit Dict Key Deletion**:
   When clearing cookies, `cookie_str` is empty. Instead of returning early, invoking `douyin_headers.pop("Cookie", None)` clears stale session credentials immediately in memory.
